  locally. Fixed by mocking `detectCores()` to return `2L` for the duration of
  `test-generateReferenceDistribution2IFC.R` (simulates a modest-core machine rather than
  suppressing the actual CRAN check — ncores ends up ≤2 either way, a legitimate case
  that must work). Committed straight to `add-testthat-and-cicd` (PR #126,
  commit `e183635`), then merged forward into `improve-docs` so PR #127 has the fix too.

**The bug:** `load()` assigns straight into the calling frame, so an object in the
`.Rdata` file overwrites a function argument of the same name — verified empirically.
`generateReferenceDistribution2IFC()` re-saved its whole frame, so files it wrote
contained `rdata`, and after this branch also `ncores`. Consequences:

- A second call on the same file silently ignored the caller's `ncores`.
- `computeInfoVal2IFC()` still uses `rdata` after `load()` (to regenerate and re-read
  the reference distribution), so a stale recorded path made it fail with
  `cannot open the connection`.

Fixed at the source (exclude the function's own arguments and scratch variables from the
save) *and* defensively on read in `computeInfoVal2IFC()`, so `.Rdata` files already
written by older versions behave. Two regression tests added and **verified to fail
without the fix**. Golden master unchanged. 124 tests pass (was 109).

Also corrected a comment in `test-generateReferenceDistribution2IFC.R` that still claimed
`ncores` could not be overridden — this branch is what changed that.

### PR #122 (community contribution) — reviewed, do NOT merge as-is
Claims a 9x speedup in `generateNoiseImage()` by replacing `apply(..., 1:2, mean)` with
`rowMeans`. **The submitted code is numerically wrong.** `rowMeans()` on a 3-D array
defaults to `dims = 1`, collapsing dims 2 *and* 3, so it returns a length-`img_size`
vector that `array(..., dim = c(n, n))` then silently recycles. Measured max abs deviation
0.21 against data whose SD is ~0.01 — not the ~1e-17 rounding difference the PR reports.
(The PR's own verification script prints `improved_noise`, a variable it never assigns,
so it cannot have run as pasted.)

`rowMeans(x, dims = 2)` is the correct form: matches `apply` to 1e-19, and benchmarks at
2.16s → 0.15s at 512px/nscales=5 — a **14x** speedup, better than claimed. Worth taking,
as our own change with credit to @hvalev. Not yet done, and no comment has been posted to
the PR — that is outward-facing and needs Ron's go-ahead.
