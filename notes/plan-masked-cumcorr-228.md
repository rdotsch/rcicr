# Plan: fix masked targetci in computeCumulativeCICorrelation() (#228)

## The bug

`computeCumulativeCICorrelation()` correlates cumulative CIs against `finalCI` with
`cor(as.vector(cumCI), as.vector(finalCI))` (line 163). `cor()` defaults to
`use = "everything"`, so a single `NA` in `finalCI` — which is what `generateCI()`
stores for every masked pixel — makes every point on the curve `NA`.

Measured in the issue: a 32px CI with a 4x4 masked corner (16 of 1024 pixels)
gives an all-NA curve; `cor(..., use = "complete.obs")` on the same pair gives 1.

## The fix

Pass `use = "complete.obs"` to the one `cor()` call at line 163.

### Why this is safe

- **Unmasked targets contain no `NA`.** `complete.obs` on a pair with no missing
  values is identical to `everything` — bit-identical output, nothing changes for
  the common case.
- **The zero-variance all-NA case is unaffected.** Responses that cancel exactly
  give a constant (all-zero) CI; `cor()` against a constant is `NA` under any
  `use` setting. That case is separately tested and documented.
- **No new failure mode.** If the mask covers *every* pixel, `complete.obs` on an
  all-NA pair gives `NA` (no complete cases), which is correct — there is nothing
  to correlate.

### What changes

Only the masked-targetci case: `NA` → real correlations over the unmasked pixels.
This is a change in returned values, so it needs a `NEWS.md` entry. The release
gate is unaffected because the reference version (v1.0.1) has no mask support in
this function and does not exercise it.
